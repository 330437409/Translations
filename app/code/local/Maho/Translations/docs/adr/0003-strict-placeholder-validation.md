# ADR-0003：占位符校验失败时阻止保存和导入

## 状态

已接受。

## 背景

界面文案经常包含运行时标记：printf 占位符、Maho 模板指令、HTML 标签。翻译时如果丢失、增加或改写这些标记，轻则显示错误，重则 `vsprintf` 报错、模板渲染异常或页面结构损坏。

后台编辑是人工操作，CSV 导入可能来自外部翻译人员，错误输入的概率更高。

## 决策

保存和 CSV 导入前做严格校验。printf、模板指令和 HTML 标签的多重集合必须和源文案一致。不一致时阻止写入，并列出缺少和多余的标记。第一期不提供“仍然保存”的绕过开关。

## 理由

- 占位符错误会直接造成页面错误，属于高风险数据。
- 严格阻断比“保存后警告”更容易测试和解释。
- 后台编辑可以立即修正；CSV 导入可以修正后重试，不会留下半批数据。
- 第一期不做 AI，人工翻译场景下阻断的代价可控。

## 后果

- 某些合法的语序调整可能被误判，例如把 `%1$s` 和 `%2$s` 互换。第一期要求保持标记多重集合一致，位置参数可以通过调整翻译文本解决。
- HTML 标签只比较标签名，不比较属性，减少误报。
- 如果业务确实需要绕过，第二期再评估“标记待审核”或“管理员强制保存”。

## 备选方案

- **只警告不阻断**：实现简单，但错误翻译会直接上线，不采用。
- **只校验 printf，不校验模板和 HTML**：覆盖不足，不采用。
- **保存后异步扫描并标记问题**：需要额外的审核状态和 UI，第一期不做。
