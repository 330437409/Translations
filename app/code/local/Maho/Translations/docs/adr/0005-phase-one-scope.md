# ADR-0005：第一期不做 AI、内联编辑和内容翻译

## 状态

已接受。二期排期部分已被 [ADR-0006](0006-phase-two-scope.md) 取代。

## 背景

参考库里既有界面文案管理，也有 AI 翻译商品内容和前台内联编辑。三类能力的用户、数据和风险都不同：

- 界面文案管理：数据量中等，写入 `core_translate`，影响所有页面。
- AI 翻译：需要 provider、API key、成本控制、草稿和审核流程。
- 内联编辑：需要改渲染输出、权限、AJAX 和大量页面回归。
- 内容翻译：涉及商品、分类、CMS 的 store view 数据和字段级复制。

如果第一期同时做，范围会失控，验证门也很难覆盖。

## 决策

第一期只做界面文案管理、扫描、CSV 往返和占位符校验。AI 辅助、内联编辑、内容翻译和超长文案支持全部放到第二期。

## 理由

- 先把最高频、最基础的“看文案、改文案、导入导出”做稳。
- 第一期不引入外部 API 依赖和成本变量。
- 不改前台渲染链路，回归范围可控。
- 第二期可以在稳定的索引和编辑接口上增加 AI 草稿和内联入口。

## 后果

- 第一期不能用 AI 批量生成翻译，翻译人员仍需离线或手工翻译。
- 前台页面不能点击文案直接编辑。
- 商品和 CMS 内容翻译仍然要另找方案。
- PRD 的 FR-10 到 FR-13 保留为第二期，不删需求。

## 备选方案

- **先做 AI，后做管理界面**：没有审核和回滚界面，风险高，不采用。
- **先做内联编辑**：需要改渲染链路，回归面最大，不采用。
- **三件事并行**：范围过大，无法在可控时间内通过验证门，不采用。
