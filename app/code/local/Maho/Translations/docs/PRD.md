# 产品需求文档（PRD）：Maho 后台翻译管理模块

> 状态：已交付@0.3.0（当前功能基线；后续计划暂停）
> 模块：`Maho_Translations`
> 代码路径：`app/code/local/Maho/Translations`
> 关联 spec：`docs/specs/translations-admin.md`

## 1. 背景与目标

Maho 的界面文案来自三处：模块 CSV 语言包、主题 `translate.csv`、数据库 `core_translate`。运行时由 `Mage_Core_Model_Translate` 按 locale、store、area 合并。Maho 目前没有后台翻译管理界面，内联翻译也已移除，管理员和翻译人员只能直接改 CSV 或手写数据库记录，无法看到缺失文案、未使用文案和文案在代码中的位置。

本模块的目标是给 Maho 后台补一个界面文案管理能力：

- 浏览、搜索、筛选某个 locale 和 store 下的界面文案。
- 查看当前生效翻译，以及它来自语言包、全局覆盖还是 store 覆盖。
- 在后台编辑翻译，保存到 `core_translate`，立即刷新翻译缓存。
- 扫描源码和语言包，识别缺失、未使用和超长文案。
- 导入、导出 CSV，方便和翻译人员或翻译公司协作。
- 保存和导入前校验占位符，避免翻译破坏页面。

### 非目标

第一期明确不做：

- 商品、分类、CMS 页面/块等内容翻译。
- AI 自动翻译。
- 前台或后台页面的内联点击编辑。
- 直接改写 vendor 里的语言包 CSV。
- 翻译记忆、术语表、机器翻译供应商管理。
- 主题 `translate.csv` 的编辑。
- `jstranslator.xml` 里 JavaScript 文案的独立管理。
- 审计日志和回滚。
- 超过 `core_translate` 字段长度限制的超长文案编辑。

## 2. 角色

| 角色 | 关注点 |
|---|---|
| 店铺管理员 | 修正界面文案，按 store 覆盖翻译，确认哪些文案还没翻译 |
| 翻译人员/翻译公司 | 导出缺失文案，离线翻译，再导入 CSV |
| 开发者 | 运行扫描，确认文案来源、模块、文件和行号，清理未使用文案 |
| Maho 运行时 | 继续用现有 `Mage_Core_Model_Translate` 加载 CSV 和 `core_translate` |

## 3. 用户故事

- 作为店铺管理员，我希望按 locale 和 store 查看所有界面文案及当前翻译，以便快速发现和修正错误翻译。
- 作为店铺管理员，我希望只覆盖某个 store 的翻译，不影响其他 store，以便同一语言下做站点级差异。
- 作为店铺管理员，我希望看到哪些文案缺失、哪些文案没有被代码使用，以便安排翻译和清理工作。
- 作为翻译人员，我希望导出缺失文案为 CSV，离线翻译后再导入，以便不用接触服务器文件。
- 作为开发者，我希望看到一条文案出现在哪些模块、area、文件和行号，以便判断它是否还能安全删除。
- 作为店铺管理员，我希望占位符不匹配时保存被阻止，以免页面报错或布局损坏。
- 作为系统管理员，我希望只有被授权的后台用户能查看、编辑、扫描和导入导出翻译。

## 6. 验收标准

### AC-01 扫描与索引

给定一个包含 PHP、PHTML、XML 和 CSV 的测试目录，运行扫描后：

- 测试文件里的 `__('...')` 和 `translate="..."` 文案被索引。
- 每条文案记录模块、area、文件、行号和是否被使用。
- 重复扫描结果稳定，不产生重复行。
- 动态文案（变量拼接、变量参数）被跳过，并在扫描结果里报告跳过数量。
- 超过 255 字符的源文案仍被索引，FR-13 起可通过长文案表编辑。

### AC-02 翻译网格

- 按 locale 和 store 筛选后，只显示该范围的文案。
- 生效翻译优先级为：store 数据库覆盖 > 全局数据库覆盖 > 语言包 CSV > 源文案。
- 状态筛选能区分缺失、已翻译、冲突、未使用和不支持编辑。
- 文本搜索同时匹配源文案和生效翻译。
- 没有扫描数据时，页面提示先运行扫描。

### AC-03 编辑与保存

- 保存一条翻译后，`core_translate` 出现或更新对应记录。
- 刷新翻译缓存后，前台或后台对应文案立即变为新翻译。
- 在某个 store 下保存只影响该 store；其他 store 继续使用全局或语言包翻译。
- 清除 store 覆盖后，该 store 恢复全局或语言包翻译。
- 清除全局覆盖后，所有 store 恢复语言包翻译。
- 保存失败时显示可读错误，不写入部分数据。

### AC-04 占位符校验

- 源文案含 `%s`、`%1$s`、`%d` 等 printf 占位符时，翻译缺少或多出占位符会被阻止。
- 源文案含 `{{var ...}}`、`{{block ...}}` 等模板指令时，指令缺少或多出会被阻止。
- 源文案含 HTML 标签时，标签名缺少或多出会被阻止。
- 源文案没有占位符时，翻译新增占位符会被阻止。
- 错误信息列出缺少和多余的占位符。

### AC-05 CSV 导出

- 可以导出当前生效翻译、缺失文案和仅数据库覆盖三种范围。
- 导出文件为 UTF-8 两列 CSV，第一列源文案，第二列翻译。
- 缺失文案导出的第二列为空。
- 含逗号、引号、换行的文案能正确转义并重新导入。
- 以 `=`, `+`, `-`, `@` 等开头的文案导出时加 `'` 前缀，重新导入后还原。
- 导出文件名包含 locale、store、范围和日期。

### AC-06 CSV 导入

- 合法 CSV 导入后，数据库记录按 locale 和 store 新增、更新或删除。
- 导入前整体校验，任意一行占位符不匹配或源文案为空时，整批不写入；长文案允许导入。
- CSV 中重复的源文案视为错误，整批不写入。
- 支持 UTF-8 BOM 和 CRLF 换行。
- 上传文件的 MIME 必须是 CSV 或纯文本，实际大小不超过 10 MB。
- 导入完成后显示新增、更新、删除、跳过数量，并刷新翻译缓存。
- 同一文件重复导入结果一致，不产生重复记录。

### AC-07 缺失与未使用

- 缺失文案是没有语言包翻译、没有全局覆盖、没有 store 覆盖的已使用文案。
- 未使用文案是语言包里有定义、但源码扫描没有找到使用位置的文案。
- 未使用项只展示，不提供删除按钮。
- 网格可以分别筛选缺失和未使用。

### AC-08 菜单与权限

- 有权限的管理员能在 System 菜单下看到 Translations。
- 没有查看权限的用户访问页面返回 403。
- 只有查看权限的用户看不到或不能执行保存、扫描、导入、导出。
- 所有写操作都校验后台表单密钥。

### AC-09 跨数据库

- 在 SQLite 上完成扫描、网格、保存、清除、导入、导出。
- 在 MySQL 或 PostgreSQL 上至少完成一次同样的流程，确认 SQL 不使用数据库专用语法。
- 单元测试和集成测试不依赖 MySQL 专用函数。

### AC-10 真实可用性

- 在开发店铺安装模块，运行扫描，编辑一条已知文案（例如 `Home page`），在 storefront 看到变化。
- 清除覆盖后，storefront 恢复原文案。
- 导出缺失文案，离线填写后导入，网格和 storefront 都能看到结果。
- 后台页面的实际操作由用户确认通过，测试绿不替代人工确认。

### AC-11 AI 辅助翻译

- AI 只创建或更新草稿，不直接修改 `core_translate`。
- 缺失文案和人工勾选的已有翻译都可以生成草稿；已有翻译在通过前保持不变。
- 1 到 3 条同步生成；超过 3 条进入 `Maho_Ai` 异步队列。
- 队列未启用时，超过 3 条被阻断；1 到 3 条仍可同步生成。
- 草稿按 `source_hash + locale + store_id` 唯一，重新生成覆盖当前草稿，不保留历史。
- 草稿可以在编辑页修改并通过或拒绝；通过前重新校验占位符和长度。
- 通过后写入 `core_translate` 或 `translation_long` 并清理翻译缓存；拒绝不修改现有翻译。
- 批量通过和拒绝按行处理，单行失败不影响其他行。
- AI 操作遵守新增的生成权限和现有保存权限。
- 使用真实 AI provider 至少完成一次生成、修改、通过和 storefront 验证。

### AC-12 超长文案

- 超过 255 字符的源文案和翻译可以保存、编辑和清除。
- 长文案写入 `translation_long`，同一 scope 不保留 `core_translate` 记录。
- 保存短文案时清理同 scope 的长文案记录。
- 长表优先于 `core_translate`，store 覆盖优先于全局覆盖。
- 运行时翻译器能加载长文案，保存或清除后缓存立即刷新。
- CSV 导出包含长文案，导入后可以往返，重复导入幂等。
- AI 草稿可以生成和通过长文案，不因 255 字符被跳过或拒绝。
- 网格按正常 missing、translated、conflict 显示，`Long` 筛选只显示 `source_length > 255` 的源文案。
- 文案受 TEXT 上限 65535 约束。

## 7. 分期（路线）

> 当前决策见 ADR-0009：0.3.0 作为功能基线，剩余二期和三期功能暂停，不排期。恢复前需要重新确认范围和验收。

- **第一期（MVP）**：FR-01 到 FR-09。后台管理界面文案，数据库覆盖，扫描，CSV 往返，占位符校验，权限和 CLI 扫描。
- **第二期**：FR-10、FR-12、FR-13。FR-10 和 FR-13 已交付；FR-12 暂停。
- **第三期**：FR-11、FR-14 及后续规模化能力。内联编辑、审计、回滚、翻译记忆、术语表，当前暂停。

## 8. 术语表

| 术语 | 含义 |
|---|---|
| locale | 语言代码，例如 `en_US`、`it_IT` |
| store / store view | Maho 的店铺视图，翻译可以按 store 覆盖 |
| area | `frontend`、`adminhtml`、`install` |
| 源文案 | 代码或语言包里作为 key 的原文 |
| 语言包翻译 | `app/locale/<locale>/*.csv` 里的翻译 |
| 全局覆盖 | `core_translate` 中 `store_id = 0` 的记录 |
| store 覆盖 | `core_translate` 中指定 `store_id` 的记录 |
| 生效翻译 | 运行时最终使用的翻译，优先级为 store 覆盖 > 全局覆盖 > 语言包 > 源文案 |
| 占位符 | `%s`、`%1$s`、`{{...}}`、HTML 标签等运行时替换或渲染标记 |
| 扫描索引 | 模块为网格和缺失/未使用分析建立的源文案与位置索引 |
