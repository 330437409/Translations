# 测试与质量门

## 原则

- 新行为先写失败测试，再写实现。测试要能在实现前红、实现后绿。
- 测试表达需求，不表达实现细节。优先测行为、边界和失败路径。
- 不声称完成，除非能出示命令和结果。
- 不跑全量 `composer test`，除非用户要求、改测试基座或复现 CI 问题。Maho 全量套件会重建测试库，耗时很长。

## 必跑

- 新增或修改的单元测试。
- 涉及数据库、缓存、ACL 的集成测试。
- `composer lint` 或至少针对修改文件运行 php-cs-fixer、PHPStan、Rector。
- 手动验证后台页面和 storefront 文案变化。

## 测试覆盖重点

- 扫描器：PHP、PHTML、XML、CSV、动态文案、行号、模块、area、超长文案。
- 占位符：printf、模板指令、HTML 标签、缺少、多余、多字节。
- CSV：转义、BOM、CRLF、重复行、长度限制、整批失败。
- 生效翻译优先级：store 覆盖、全局覆盖、语言包、源文案。
- 缓存：保存和导入后清理 `translate` 缓存。
- ACL：未授权用户被拒绝。
- 跨数据库：SQLite 本地，MySQL/PostgreSQL 尽量或交给 CI。
- AI 草稿：同步/异步生成、草稿唯一性、通过/拒绝、占位符校验、批量部分成功、任务对账和 ACL。
- 长文案：存储路由、长表/core 互斥、运行时资源合并、CSV 往返、AI 草稿和缓存刷新。

## 证据

完成声明必须包含：

- 测试命令和通过结果。
- 手动验收步骤和结果。
- 如涉及页面，提供截图或明确的页面路径。
- 未运行的测试和原因。

## 红线

- 跳过测试直接实现。
- 测试绿了但后台页面不可用。
- 用“应该可以”代替实际验证。
- 为通过测试而弱化断言或删除失败测试。
